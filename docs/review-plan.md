# План Code Review: Модуль расчета скидок (src/discount.py)

## 1. Цели проведения ревью
* **Точность расчетов:** Исключить округления в пользу пользователя/системы, ведущие к финансовым расхождениям.
* **Защита от фрода (Anti-fraud):** Убедиться, что комбинация промокодов не позволяет снизить цену ниже допустимого лимита (70% от базовой стоимости).
* **Корректность применения скидок:** Проверить строгую последовательность шагов: Базовая скидка -> Промокоды -> Уровень лояльности.

## 2. Измеримые критерии оценки (Definition of Done для PR)
* **No Magic Numbers:** Полное отсутствие хардкода числовых коэффициентов. Все переменные скидок должны запрашиваться из конфигуратора или констант.
* **Валидация входных данных:** Обязательная проверка типов (`cart_sum` > 0, `tier` как целое число, `promos` как валидный итерируемый список).
* **Покрытие тестами:** Покрытие ветвлений (branch coverage) модуля `discount.py` должно составлять не менее **85%**.

## 3. Участники и роли
* **Автор кода (Developer):** Разработчик микросервиса корзины.
* **Рецензент (Reviewer):** Кросс-разработчик команды или QA-инженер автоматизации (проверяет граничные условия).
* **Утверждающий (Tech Lead):** Контролирует архитектурное соответствие и закрывает пул-реквест.

## 4. Раздел эскалации споров
В случае возникновения разногласий по поводу архитектурного стиля или оптимизации алгоритма:
1. Обсуждение переносится в комментарии к конкретной строке Pull Request.
2. При отсутствии консенсуса в течение 24 часов, вопрос выносится на синхронный созвон с **Tech Lead** (`@твой-github-никнейм`), чье решение является финальным и обязательным к исполнению.
